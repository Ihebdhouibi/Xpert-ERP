# 05 — API Design

REST over HTTPS, JSON. OpenAPI 3.1 is auto-generated by FastAPI and is the contract. This document is the convention layer that the contract follows.

---

## 1. Base conventions

- Base URL: `/api/v1/`. Major versions only in the URL. Minor compatible changes are additive (new fields, new endpoints).
- Resource paths in **plural snake_case**: `/api/v1/repair_orders/{id}`.
- Field names in JSON: **camelCase**.
- All identifiers in URLs and payloads: UUID where exposed; never raw DB BIGINT for external endpoints (M2 onward will use UUID surrogate columns where needed).
- Dates and timestamps: ISO 8601 with timezone (`2026-05-14T09:00:00Z`).
- Money: object `{ "amountMinor": 12345, "currency": "EUR" }`. Never a float.
- Boolean fields: prefixed with `is`/`has`/`can`.
- All list responses are paginated; default page size 25, max 200.
- All write endpoints require `Idempotency-Key` header for the operations marked idempotent below.

---

## 2. Authentication

- Login: `POST /api/v1/auth/login` → returns short-lived access token (15 min) and a refresh token (rotating, 7 days).
- Token in `Authorization: Bearer <jwt>`. Refresh via `POST /api/v1/auth/refresh`.
- Logout: `POST /api/v1/auth/logout` invalidates the refresh token.
- Password reset: `POST /api/v1/auth/password_reset_request` and `POST /api/v1/auth/password_reset_confirm`.

JWT claims: `sub` (user id), `garage_id`, `roles` (list of role codes), `permissions` (optional explicit list), `iat`, `exp`, `jti`.

---

## 3. Authorization

- Every endpoint declares the permission code it requires (see [06_RBAC_DESIGN.md](06_RBAC_DESIGN.md)).
- Missing permission → `403`. Missing authentication → `401`. The two are never confused.
- Tenancy is implicit: the user's `garage_id` is the only one they can touch unless they are a super-admin with explicit override.

---

## 4. Response envelope

Single-item:

```
{
    "data": { ... resource ... },
    "meta": { "requestId": "..." }
}
```

List:

```
{
    "data": [ { ... }, { ... } ],
    "meta": {
        "requestId": "...",
        "page": 1,
        "pageSize": 25,
        "totalCount": 132,
        "totalPages": 6
    }
}
```

Error:

```
{
    "error": {
        "code": "validation_error",
        "message": "human readable",
        "details": [ { "field": "vehicle.registration", "issue": "duplicate" } ],
        "requestId": "..."
    }
}
```

Standard error codes: `validation_error`, `not_found`, `conflict`, `forbidden`, `unauthenticated`, `rate_limited`, `internal_error`, `dependency_error`.

---

## 5. HTTP status code policy

| Code | Use                                                      |
|------|-----------------------------------------------------------|
| 200  | Success on read or update                                |
| 201  | Resource created                                         |
| 202  | Accepted for async processing (OCR, batch reports)       |
| 204  | Success with no body (logout, idempotent delete)         |
| 400  | Malformed request (body, type)                            |
| 401  | Missing/invalid auth                                      |
| 403  | Authenticated but unauthorized                            |
| 404  | Resource not found (or hidden by tenancy)                 |
| 409  | Conflict (optimistic concurrency, duplicate, state)       |
| 422  | Validation failure (semantic)                             |
| 429  | Rate limited                                              |
| 500  | Unhandled (with a request_id in body for support)         |
| 503  | Dependency unavailable                                     |

A tenant trying to access another tenant's resource returns `404`, not `403`, to avoid leaking existence.

---

## 6. Filtering, sorting, search

- Filters as query params: `?status=in_repair&assignedMechanicId=...`.
- Search as `?q=...` on endpoints that support full-text.
- Sorting: `?sort=-issuedAt,docNumber` (prefix `-` for descending; default order is per-endpoint sensible default).
- Pagination: `?page=2&pageSize=50`. Page-based for the UI; cursor-based on hot streams (audit log, stock movements).

---

## 7. Optimistic concurrency

Resources that carry `version`:

- The response includes `"version": 7` in the data.
- Update requests must send `If-Match: 7`.
- A mismatch returns `409 conflict` with the current version in the body.

---

## 8. Idempotency

`POST`s that produce side effects (issue invoice, record payment, send notification, generate document, run OCR) accept an `Idempotency-Key` header. The server stores the response keyed by `(user_id, endpoint, key)` for 24 hours and returns the cached result on retry.

---

## 9. File upload

- Small files (< 10 MB): `multipart/form-data` to `POST /api/v1/documents`.
- Large files (videos, scans): two-step. `POST /api/v1/documents/upload_url` returns a signed object-storage URL; client uploads directly; client then `POST /api/v1/documents/finalize` with the storage key.
- Server validates MIME against `CFG_FILE_MAX_SIZE_MB` and an allow-list per category.

---

## 10. WebSocket / SSE (selective)

- Workshop kanban gets live updates: `GET /api/v1/realtime/workshop` over Server-Sent Events. Events: `repair_order_status_changed`, `repair_order_created`, `repair_order_assigned`.
- Notifications: `GET /api/v1/realtime/notifications` SSE for in-app banners (vehicle ready, low stock).

Only modules that benefit (workshop board, dashboard KPIs in M10) use realtime. Everything else is request-response.

## 12. Versioning policy

- Additive changes (new endpoints, new optional fields, new enum values) ship under `v1`.
- Breaking changes go to `v2`. Both versions run in parallel for at least one full release cycle.
- Deprecations are announced via `Deprecation` and `Sunset` response headers per RFC 8594 / draft 9745.

---

## 13. Rate limiting and abuse

- Per user: 600 req/min default; 60 req/min on auth and password reset.
- Per IP: 1200 req/min default.
- 429 responses include `Retry-After`.

---

## 14. Backward compatibility tests

A schema-diff job runs on every PR: it compares the OpenAPI of the PR against the last `stable-testing` and fails the build on any breaking change (removed field, type narrowed, status removed).
