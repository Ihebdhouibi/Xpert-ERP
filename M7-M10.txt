Models (purchase_order/models.py):

PurchaseOrderLine: quantity_ordered, unit_price_ht, quantity_received, quantity_invoiced, match_flag
Service (purchase_order/service.py):

create_po → generates doc_number via sequence, resolves supplier + part public IDs
send_po → draft → sent
receive_po → creates stock in_ movement atomically per line, updates status (partially_received / completed), recomputes match flags
cancel_po → draft/sent/partially_received → cancelled
update_invoiced_qty → three-way match re-evaluation per line
create_po_from_alert → one-click PO from low-stock alert
Three-way match (tolerance from CFG_PO_MATCH_TOLERANCE_PERCENT, default 5%):

qty_mismatch → |ordered − received| / ordered > tolerance
inv_mismatch → |received − invoiced| / received > tolerance (when invoiced > 0)
API (purchase_order/router.py):

GET/POST /purchase-orders
GET/PUT /purchase-orders/{id}
POST /purchase-orders/{id}/send|receive|cancel
PATCH /purchase-orders/{id}/lines/{line_id}/invoice
POST /stock/alerts/{id}/create-po
