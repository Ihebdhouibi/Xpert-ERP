problem of sign in

FastAPI 0.115.x added a stricter startup-time assertion — any route with status_code=204 (No Content) must explicitly declare that it has no response body, otherwise FastAPI refuses to boot.

Before 0.115, FastAPI was lenient: if you wrote -> None as the return type on a 204 route, it silently accepted it. In 0.115 it now enforces it hard at import time with:


assert is_body_allowed_for_status_code(status_code)
# AssertionError: Status code 204 must not have a response body
The two correct patterns that satisfy the check:


# Option A — response_model=None (explicit "no schema")
@router.delete("/foo", status_code=204, response_model=None)
async def delete_foo() -> None: ...

# Option B — response_class=Response (returns a raw Response object)
@router.delete("/foo", status_code=204, response_class=Response)
async def delete_foo() -> Response:
    return Response(status_code=204)
Why only two routes were broken — most routers in your codebase were already using one of those patterns correctly. The inspection and media routers were written slightly earlier and missed it. The bug was dormant because those modules had never actually been loaded until now (they were untracked in git and the server hadn't been started since they were added).-
