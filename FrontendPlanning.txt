Frontend Gameplan — Xpert ERP (Garage Workshop)
Current State in One Line
The backend is feature-complete (25 modules, 28 migrations). The frontend has 22 pages wired up, but they're built page-by-page with no shared shell, no component library, and very inconsistent UX. It works, but it doesn't feel like a product yet.

Phase 1 — App Shell & Design Foundation (Highest ROI)
This is the most critical phase. Everything else builds on it.

1.1 — Sidebar Navigation Shell
Right now there is no persistent nav — users go back to a dashboard tile grid. That's bad UX for a daily-use ERP. We need:

Fixed left sidebar (collapsible on desktop, drawer on mobile/tablet)
Grouped sections: Workshop | Stock & Purchasing | Billing | Admin
Active route highlighting, permission-gated menu items
Top header: garage name, notifications bell, user avatar + logout
1.2 — Global Toast/Snackbar System
Zero feedback on mutations right now. Need a useToast() hook + provider so every page can fire success/error/warning messages consistently.

1.3 — Shared Component Library (these get reused on every page)

DataTable — paginated, sortable, with a search bar and filter chips; replaces 10+ hand-rolled tables
PageHeader — title, breadcrumbs, action button slot
StatusChip — semantic color per status (RO: OPEN=blue, IN_PROGRESS=orange, DONE=green, etc.)
CurrencyDisplay — formats integer minor-units (centimes) to €XX.XX
ConfirmDialog — reusable destructive action confirmation
EmptyState — empty list/no results placeholder
LoadingSkeleton patterns — replace raw CircularProgress spinners
1.4 — Error Boundary + 404 page
No error boundary exists. The app will white-screen on any uncaught render error.

Keep this in your mind in  terms of UI/UX thinking : 
You are taking the role of a senior product designer and frontend architect working at a top SaaS company.

Your mission is not simply to make the interface functional, but to create a modern, premium, enterprise-grade experience that feels comparable to Linear, Notion, Stripe Dashboard, Vercel, Jira, HubSpot, and modern Microsoft applications.

UI/UX principles:

1. Visual Hierarchy
- Users must immediately understand where to look first.
- Important actions should stand out.
- Reduce visual noise.

2. Whitespace
- Use generous spacing.
- Avoid crowded layouts.
- Let components breathe.

3. Consistency
- Consistent colors, spacing, typography, border radius, shadows, and component behavior.
- Every page should feel like part of the same design system.

4. Modern Enterprise Design
- Clean, professional, premium.
- Avoid outdated admin panel aesthetics.
- Avoid excessive gradients, flashy effects, or excessive colors.

5. Information Density
- Optimize for business users who spend hours per day in the application.
- Show information efficiently without overwhelming users.

6. Accessibility
- Strong contrast.
- Readable typography.
- Clear focus states.
- Mobile and desktop responsive.

7. User Efficiency
- Minimize clicks.
- Surface the most common actions.
- Use contextual actions where appropriate.

8. Dashboard Design
- KPI cards should be visually distinct.
- Charts should be readable and not decorative.
- Tables should be easy to scan.

9. Forms
- Reduce cognitive load.
- Group related fields.
- Use clear labels and validation messages.

10. Tables
- Sticky headers where appropriate.
- Search, filtering, sorting.
- Clear row actions.

11. Interactions
- Smooth transitions.
- Subtle animations only.
- No distracting effects.

12. Design System
- Build reusable components.
- Use a scalable spacing system.
- Use a modern typography scale.

For every screen you design:
- Explain UX decisions.
- Explain visual hierarchy.
- Explain why each layout choice improves usability.
- Prioritize user experience over implementation convenience.

The final result should feel premium, modern, elegant, and production-ready.

What Phase 1 got right:

Inter font, proper type scale, letter spacing — the foundation is solid
Dark navy sidebar matches the Linear/Vercel aesthetic
Component tokens are consistent (same radius, same shadows, same color system everywhere)
The theme overrides are deep enough that every MUI component inherits the right defaults
Where I need to push harder in the next phases:

The dashboard hero gradient is slightly too decorative — Linear and Vercel use flat, calm backgrounds with strong typography doing the heavy lifting. I'll tone that down.

The KPI metric cards work but they're missing the trend context — a number without "compared to last month" means nothing to a business user. That's a UX failure, not just a visual one.

The existing 22 pages (customers list, repair order detail, etc.) are still raw — they're just sitting inside the shell without benefiting from the new component library. DataTable, PageHeader, StatusChip, EmptyState — none of those are wired into the actual pages yet. That's Phase 4 work, but it matters a lot for consistency.

One thing I'd push back on slightly:

Point 4 says avoid excessive gradients — I agree. But a garage ERP is not Stripe. The users are workshop managers, mechanics, and accountants who sometimes use this on a tablet in a noisy garage. Information density and contrast need to be slightly higher than a pure B2B SaaS product like Linear. Think more Jira than Notion. I'll keep that tension in mind when designing every screen.

My commitment going forward:
Every page I build, I'll call out the UX decisions and hierarchy reasoning before writing a line of code. If something is a shortcut that compromises the experience, I'll flag it rather than hide it.
